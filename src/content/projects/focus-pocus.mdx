<Chapter stage="problem" visual="screenshot" draft>

Generative AI is good at breaking a goal into steps with deadlines, whether that is an MBA assignment, a side project or a new habit. Getting those steps into OmniFocus was the slow part.

The route was to ask for TaskPaper text and import it, and the formatting rarely came out clean. Each model did it a little differently, and every import needed fixing by hand.

The aim was to let Claude Desktop create and manage the projects and tasks directly, by conversation, and to learn agentic coding on a problem that was low-stakes enough to fail at.

</Chapter>

<Chapter stage="constraints" draft>

OmniFocus can only be automated on a Mac, so everything had to run locally and ask macOS for permission.

The work had to happen in the background. Opening the app or an overlay for every change would defeat the purpose.

Claude had to read tasks as well as write them, to answer questions and to avoid duplicating what was already there.

JXA is not a fast interface. Even a database of 1,600 tasks needed caching and pagination before bulk changes were usable.

</Chapter>

Four routes were open, including carrying on as before. Only two of them could both read and change tasks without bringing OmniFocus to the front.

<Chapter stage="built" visual="architecture" draft>

Focus Pocus is an MCP server written in TypeScript on Node.js, about 3,800 lines. It gives Claude Desktop more than 35 tools for tasks, projects, tags and perspectives, and reads dates written as "tomorrow at 2pm" or "next Friday".

Behind the tools are 39 JXA scripts that do the work inside OmniFocus. Many of them only ran reliably when saved as files, which gave them a cold start, so a cache with pagination keeps large databases responsive.

Every script uses a safeGet pattern: if the normal way to read a value fails, try another way, and fall back to a sensible default rather than crash. A diagnostics tool checks permissions and the connection, and an install script sets up Claude Desktop.

<Chapter stage="outcome" visual="packing-list" draft>

The real test was a packing list for a trip to France: multiple projects, subtasks and natural-language dates, created in OmniFocus from one conversation. It worked with one small hiccup on dates and little clean-up.

Tasks can now be created, updated and managed by conversation, including in bulk. Claude can open the Inbox, Forecast, Flagged and Projects views and balance work across the week.

It is in daily use, with the caveat that an AI using the tool can still do something unexpected, so OmniFocus backups stay switched on.

</Chapter>

<Chapter stage="lessons" draft>

Managing context is a full-time job. Even with the API docs in front of it, Claude made assumptions, dropped the safeGet pattern more than once and had to be pointed back to the documentation. A knowledgeable human in the loop caught the mistakes.

Most systems are not modern. JXA is Mac-specific, slow and thinly documented, and MCP's value was in translating between that dialect and the AI. The same gap shows up in healthcare systems that were never designed with AI in mind.

Performance and failure both need planning. Claude assumed OmniFocus would answer like a web service, and generated try/catch blocks without thinking through how things actually fail.

The full account is in the post [Building Focus Pocus: what I learned about AI coding and integration](/writing/building-focus-pocus-what-i-learned-about-ai-coding-and-integration/).

</Chapter>
