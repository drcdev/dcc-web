## Problem

Side projects were scattered across repositories and app stores with nothing to tie them together or say why they exist.

The aim was a single page on drc.dev that lists each project with a screenshot, its stack and a short description, and costs nothing to keep online.

## Options

Three routes were open. Two of them were already paid for, but neither put the projects on their own domain in their own style.

- **Free to host**: No server and no monthly bill for a page that changes a few times a year.
- **On its own domain**: drc.dev, not a page inside someone else's site.
- **Easy to add a project**: A new project is one entry, with Markdown for the description.
- **A terminal look**: Box-drawing borders, bracketed buttons and a monospace typeface.

| Option | Free to host | On its own domain | Easy to add a project | A terminal look |
| --- | --- | --- | --- | --- |
| A GitHub profile README | Yes | No | Yes | Partly |
| A page on the Ghost blog | Yes | Partly | Partly | No |
| **A Next.js static site on GitHub Pages** | Yes | Yes | Yes | Yes |

Why a Next.js static site on GitHub Pages won: it was the only route that met all four constraints, and the deploy workflow is one file that GitHub runs.

## Build

The first drc.dev was a Next.js 15 site in TypeScript, exported to static HTML. Each project is an entry in one file, with its description in Markdown, its technologies, a category and its links.

A small component library gives the terminal look: a box with corner marks, a button in square brackets and a badge for each technology. Tailwind v4 defines the colours in CSS, with a rust accent.

Two of the apps need a privacy policy for their store listings, so the site also publishes a privacy page for each of them. A GitHub Actions workflow builds and deploys the site to GitHub Pages on every push to main.

The site has been the home of these projects on drc.dev since December 2025, with four projects and two privacy pages, at no hosting cost.

It is now being replaced by this site, which tells the story of each project rather than listing its features.

## Lessons

A list of features and technologies says what a project is but not why it exists or what was learned. That gap is what the current drc.dev is built to close.

Keeping the privacy policies on the same site as the portfolio tied the app store listings to the site's address, so any move has to keep those addresses working.
