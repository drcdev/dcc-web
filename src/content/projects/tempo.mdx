<Chapter stage="problem" visual="screenshot" draft>

A routine with rounds, reps, left and right sides and rest periods is hard to follow from a stopwatch. The eyes end up on the screen instead of on form.

The aim was a timer that speaks each transition and countdown, so a routine can run from start to finish without touching the phone.

</Chapter>

<Chapter stage="constraints" draft>

A workout happens wherever there is floor space, so the app had to work with no connection and no account.

The same routine should be usable on an iPhone, an Android phone or in a browser, and a change on one device should be able to reach the others.

Bilateral steps are the awkward part. A step can run for the left side, then the right side, repeat for a number of reps, and sit inside a round that repeats as well.

Recovery periods needed their own countdown, with a way to skip one when the rest is not needed.

</Chapter>

<Chapter stage="options" draft>

Three routes were open. The first two would have been less work, but neither handled sides and reps on every platform.

<Chapter stage="built" visual="architecture" draft>

Tempo is a Flutter app for iOS, Android and the web. Routines are built from steps, each with its own duration, reps, sides and recovery, and the timer announces every transition by text to speech.

Everything is stored on the device in a Drift SQLite database, so the app is fully usable offline. State and dependencies are managed with Riverpod, and the interface uses a custom glassmorphism design system called FLXIT.

Cloud sync is optional. Signing in with a magic link syncs routines, history and preferences through Supabase, with changes queued while offline. Workouts can also be written to Apple Health or Health Connect when that is switched on. The [privacy policy](/privacy/tempo/) sets out what stays on the device.

</Chapter>

<Chapter stage="outcome" draft>

A routine can be started and finished without looking at the phone. The voice calls each step, each side and each rest, and the progress bars show where the routine is up to.

Routines can be duplicated, run in reverse and reviewed in a history with analytics. The current version is 0.11.0, which added cloud sync.

</Chapter>

<Chapter stage="lessons" draft>

Offline first made sync harder later. Every change had to be queued and replayed, and deleted records are kept for 90 days so devices can agree.

A timer needs tighter control than generated state providers give, so the timer engine ended up as a hand-written provider while everything else stayed generated.

</Chapter>
