# Tasks: Critical Thinking Questions on Writing Posts

**Input**: Design documents in `specs/022-critical-thinking-questions/` (spec.md, plan.md, research.md, data-model.md, contracts/, quickstart.md, checklists/)

**Prerequisites**: plan.md, spec.md. Constitution v2.2.0 is already amended (do not redo it).

**Tests**: Mandatory (Constitution Principle I). Every story has its test tasks first, written to fail before the implementation they cover. Each test task names its one primary layer (unit, component, build, worker, E2E, accessibility, visual or budget) per "Where a test goes" in `docs/testing.md`; a second layer appears only with a written reason. No test calls the real Workers AI model: worker tests inject a fake `AI` and a fake `ASSETS`, E2E and accessibility tests stub `/api/questions` with `page.route`.

**Major change (Principle III)**: yes. Auto-merge stays off. The `[PREVIEW-CHECK]` tasks at the end need Don (live Cloudflare access or a look at the preview deployment); implement subagents leave them.

**No test is red by design (Principle II)**: during implementation `wrangler.jsonc` keeps the **current** database names and ids (`dcc-web-contact`, `dcc-web-contact-preview`), so every deploy, preview and test stays green. The new migration is additive (two new tables), so it applies to whichever database the `DB` binding points at. Deploy scripts and the Playwright command apply migrations by the binding name `DB`, never a database name, and the setup check reads the names from `wrangler.jsonc`, so Don's swap commit (T052) changes `wrangler.jsonc` only. The config and environment tests assert the D1 configuration's shape and internal consistency, not live ids or the new names, so they are green before and after that commit. Every task ends on a green suite; the gate exits zero before the PR.

## Format: `- [ ] [ID] [P?] [Story?] Description with file path`

- **[P]**: different files, no dependency on an incomplete task
- Row ids (Q01..Q29, P01..P24, W01..W05) refer to `contracts/questions-api.md`, `contracts/questions-panel.md` and `contracts/worker-config.md`
- Node: run `node -v`; if not the `.nvmrc` version, `source ~/.nvm/nvm.sh && nvm use` in the same Bash command as any `pnpm`/`wrangler` call. Wrangler calls that use the dashboard login pass `--env-file /dev/null`. Never run `wrangler versions secret put` or `wrangler versions deploy`.

**Inner loop and gate.** `pnpm run verify:quick` runs secret lint, lint, type check, the unit and component tests, the worker tests and the real `astro build`. It is the inner-loop check for implement and fix subagents. It leaves out the build-fixture tests and every Playwright project, so it never counts as the gate. The full `pnpm run verify` runs the whole gate (secret lint, lint, type check, unit, component, build-fixture and worker tests, build, and every Playwright project: E2E, accessibility, sections, performance budget and visual), and it is the only check that counts before a PR. There is no scoped or tiered local gate: a green slice run is not a green gate.
